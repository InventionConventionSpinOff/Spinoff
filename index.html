Spin Off

A soccer ball that measures every kick. Sensors inside the ball record speed, spin, launch angle and how cleanly you struck it, send the numbers to a web app over Bluetooth, and an AI coach turns them into advice.

Built by Sahil and Skyler, 7th grade · Invention Convention 2026

Open the web app Read the firmware

Why we built it

Professional clubs measure their players with camera tracking, GPS vests and force plates. Those systems cost tens of thousands of dollars and need staff to run them. Youth players, school teams and people who just play for fun don't get any of that data, so they improve by feel.

We wanted the same kind of numbers for anyone with a ball and a phone. Spin Off is a small sensor package that fits inside a regulation ball, runs on a 1000 mAh battery, and talks to a web page in Chrome. The extra hardware costs under $40 per ball. There's no subscription and no account.

What it measures

MetricHow the ball gets it
SpeedAcceleration is added up over the moment of impact, with gravity removed, to get the ball's velocity. Up to about 70 mph.
SpinThe gyroscope measures rotation after the kick and labels it topspin, backspin, sidespin or mixed.
Launch angleThe direction of the velocity at the end of the impact, so it works for ground passes too.
Impact forceThe peak G-force during contact (the sensor reads up to ±16 G).
Strike qualityThe microphone listens to the contact and scores it 0–100: clean, mishit or off-center.
Kick typeRules on speed, angle, spin and contact time sort each kick into power shot, curve ball, chip, lob pass, ground pass or header.

The web app also keeps personal bests, a consistency score and an improvement trend for the session, lets you mark shots on a field map, and exports everything as CSV or JSON.

How it works

  1. Detect. The ball waits until it feels more than 5 G. It only counts a kick if the force reaches 7 G with real rotation behind it, which filters out catches, drops and bounces.
  2. Measure. For the next 160 ms it records acceleration, rotation and sound from the microphone.
  3. Process. The firmware filters out noise and works out speed, spin, launch angle, strike quality and kick type.
  4. Send. All of it goes to the web app as one JSON message over Bluetooth, in under 300 ms from contact.
  5. Coach. Every five kicks the ball adds training tips. In the web app, AMIR can analyze the whole session.
Technical details: firmware, physics and data format

Kick detection

The firmware is a state machine: IDLE → DETECTING → KICK_DETECTED → SPIN_SAMPLING → ANALYZING → SENDING. Crossing 5 G (KICK_ENTER_G) starts the 160 ms detection window. A kick is confirmed only if the peak reached 7 G (KICK_CONFIRM_G) with at least 150 °/s of rotation, and the threshold was crossed exactly once. Catches and bounces cross it several times; a clean kick crosses it once.

// Two-tier gate: enter at 5G, confirm at 7G + 150 dps gyro
bool strong  = (capPeakG >= KICK_CONFIRM_G) &&
               (capPeakG >= 9.0f || capPeakGyroMag >= KICK_GYRO_CONFIRM);
bool single  = (kickCrossCount <= KICK_MAX_CROSSINGS);
bool settled = (magF < KICK_SETTLE_G);

if (strong && single && settled) {
  enterState(S_KICK_DETECTED);
} else {
  // Rejected: back to IDLE with a 300 ms refractory period
  refractoryUntil = millis() + (REFRACTORY_MS / 2);
  enterState(S_IDLE);
}

After a confirmed kick, detection is paused for 600 ms so one strike can't register twice as the ball slows down.

Filtering

A low-pass filter with a fixed setting has to choose between reacting fast and smoothing well. The firmware changes the setting with the state: fast during impact so no peak gets cut off, slow at rest so the noise averages out.

float currentAlpha() {
  switch (state) {
    case S_DETECTING:
    case S_KICK_DETECTED: return 0.85f;  // ALPHA_IMPACT
    case S_SPIN_SAMPLING: return 0.50f;  // ALPHA_SPIN
    default:              return 0.35f;  // ALPHA_IDLE
  }
}
// Every sample: smoothed = alpha * raw + (1 - alpha) * previous
fAx = a*ax + b*fAx;

While the ball is still, it slowly re-calibrates its gravity and gyro readings (3% per sample), so it stays accurate as the temperature and its position change.

Speed

Speed comes from adding up acceleration over the impact window. To do that, gravity has to be subtracted from every reading, and because the ball is spinning, the direction of gravity keeps changing. The firmware tracks it with the gyroscope:

// Rotate the tracked gravity vector using gyro angular velocity
float omX = fGx * 0.01745329f;  // deg/s to rad/s
float omY = fGy * 0.01745329f;
float omZ = fGz * 0.01745329f;

gravKx += (omY*gravKz - omZ*gravKy) * dt;
gravKy += (omZ*gravKx - omX*gravKz) * dt;
gravKz += (omX*gravKy - omY*gravKx) * dt;

// Subtract rotated gravity, then integrate to velocity
float linAx = (rawAx - gravKx) * 9.81f;
velX += linAx * dt;

Launch angle is atan2(|vZ|, vHoriz) of the final velocity, so it doesn't depend on the ball leaving the ground.

Data format

Each kick is one JSON object, sent over a single Bluetooth characteristic in 160-byte pieces 20 ms apart and ending with a newline. The web app puts the pieces back together.

{
  "kick":    { "number": 12, "classification": "curve_ball", "powerScore": 74 },
  "motion":  { "speedMph": 38.4, "launchAngle": 22.0, "curlDegrees": 11.2 },
  "spin":    { "rateRPM": 212, "axis": "sidespin_left", "mixedSpin": false },
  "strike":  { "quality": 83, "classification": "clean", "contactMs": 9 },
  "session": { "totalKicks": 12, "consistencyScore": 77, "improvementTrend": "improving" },
  "personalBests": { "speedMph": 54.1, "newBestBroken": false },
  "battery": { "percentage": 82, "lowBattery": false },
  "recommendations": ["Your spin rate is inconsistent - focus on a repeatable foot contact point"]

AMIR, the AI coach

AMIR is the coach in the web app. It runs on gpt-oss-120b, an open large language model from OpenAI, through Groq's API. When you ask for feedback, the app sends AMIR your session numbers (speeds, spin, consistency, trend and the type of your last kick) along with instructions we wrote about how to coach. AMIR writes back an assessment, three things to work on and a drill. It can also build a four-week training plan, or you can just chat with it about your kicks.

Training tips from the ball

The ball also gives its own tips, without the internet. Every five kicks the firmware checks the session against rules we wrote after talking to coaches, and sends up to three tips:

  • Consistency score under 60 → plant your standing foot the same way each kick.
  • Spin changing by more than 80 RPM between kicks → find a repeatable contact point.
  • Average launch angle under 18° → aim higher on the ball. Over 55° → strike through the center.
  • Fast kicks with little spin → work on adding spin for curve and dip.
  • Average speed under 25 mph → follow through fully and speed up the kicking leg.
What the coaches told us

Weak shots

"Your plant foot should land 6–8 inches beside the ball, pointing at your target."
"Drive through the center of the ball with your laces, not your toe."
"Follow all the way through. Your kicking leg should finish above hip height."

Curve balls without enough spin

"Strike the inside edge, not the center. Aim for the outside quarter of the ball."
"Angle your approach 30–45 degrees to the target line."
"Use the inside of your foot. It gives you more surface for spin than the laces."

Shots that go too high

"Keep your body over the ball. Leaning back at contact is the main cause of high shots."
"Your follow-through should stay level. If your leg swings up, that's where the ball goes."

A note from us

Now that we look back at Spin Off, we see how far we've come. The obstacles we've overcome, the moments that challenged us, and the progress we didn't always recognize while it was happening.

When we first started, it was just an idea: a soccer ball that could measure performance. But turning that idea into something real was far from simple. There were moments when the data didn't make sense, when our system failed in ways we didn't expect, and when we had to step back and rethink everything we had built. At times, it felt like we were going in circles, fixing one problem only to discover another.

But looking back, those moments weren't setbacks in the way we first saw them. They were part of the process. Every error forced us to understand our system more deeply, every failure pushed us to improve our design, and every revision brought us one step closer to something that actually worked.

And even when things got hard, we weren't alone. We had people who supported us in different ways, through simple encouragement like "keep going," through advice when we were stuck, and through late night conversations that helped us stay motivated when things weren't working the way we hoped. Those moments didn't always feel significant at the time, but they became part of what carried us forward.

Right now, it's 10:30 PM as we write this. And maybe that says something about the project itself. Spin Off wasn't built in a single moment of inspiration. It was built across late nights, early mornings, long debugging sessions, and quiet moments of thinking things through when no one else was around. Most of those moments we won't remember clearly, but together they shaped everything that we've built here.

The good and the bad are both part of this journey. The successes gave us confidence, and the failures taught us patience. Together, they shaped not only our invention, but also how we think as engineers, problem solvers, and learners.

In the end, Spin Off represents something bigger than technology. It represents the belief that improvement should never be guesswork, but something you can see, measure, and build on every day.
